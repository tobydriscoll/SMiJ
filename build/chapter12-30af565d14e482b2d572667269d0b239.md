::::{note} NaN values
:icon: false
In line 26 of [Program 30](#p30), I have replaced all the zero error values with `NaN` (Not a Number). That's what causes the disconnected points you can see in the lower two plots of [Output 30a](#output30a). 

A `NaN` value can arise as the result of an undefined or indeterminate operation. Traditionally, it has also been used to represent missing values, and it remains convenient to use it that way in plots. But Julia also offers a separate `missing` value for that purpose, which is more appropriate for working with other kinds of data.

This brings up an amusing bit of Julia:

```{code-cell}
NaN isa Number
```

`NaN` is a special floating-point value, and all floating-point values are of type `Number`, so the assertion is true. 

:::{caution}
Numerical operations and comparisons involving `NaN` always result in `NaN`. Most notoriously,

```{code-cell}
NaN == NaN
```

To test for a `NaN` value, you should use the `isnan` function.
:::

::::{note} Extended precision
:icon: false
Double precision is called `Float64` in Julia. Base Julia has some less-precise types, such as `Float32`, and some more-precise types, such as `BigFloat`, which has variable precision at the cost of speed. There are also add-on packages such as `DoubleFloats` and `MultiFloats` that can give higher fixed precision with speed between `BigFloat` and `Float64`. All that Clenshaw–Curtis requires is basic arithmetic and the cosine function, so it is easy to generalize. 

:::{code-cell}
T = BigFloat
setprecision(100)    # 100 bits of precision, about 30 decimal digits
println("first BigFloat after 1 is ", nextfloat(one(T)))
:::

:::{caution}
Some operations, such as the ratio of integers, default to `Float64`, which limits the precision of all future operations with the result. Cast integers to the desired type before the division.
:::

Thus, to define `q` in line 6 of @clencurt, I explicitly cast the numerator to have type `T`. Since the denominator is an integer, which has infinite precision, it will be implicitly converted to `T` as well before the division is performed.

Now we can integrate as accurately as we like:

:::{code-cell}
x, w = clencurt(40, T)
I = sum(w * exp(2x) for (x, w) in zip(x, w))
println("clencurt integral = ", I)
println("error = ", sinh(T(2)) - I)
:::

If we want to extend `gauss` to work in higher precision, we need an eigensolver that works with that type. Those exist in `GenericLinearAlgebra`, but the relative cost is much higher than for Clenshaw–Curtis.

::::{note} `SymTridiagonal`
:icon: false
The `SymTridiagonal` type is a special type for symmetric tridiagonal matrices. It is used here because the matrix in the Golub–Welsch algorithm has those properties, and the eigensolver for that case is a lot more efficient than the general-purpose one.
