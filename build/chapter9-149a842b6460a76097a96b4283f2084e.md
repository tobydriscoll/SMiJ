Now that you're becoming comfortable with Julia basics, it's a good time to say a bit more about its type system. For example, we've worked with Toeplitz matrices several times. But to be precise, a `Toeplitz` matrix isn't a `Matrix` in Julia:

:::{code-cell}
using ToeplitzMatrices
col = [0.; -2; 6; zeros(3)]
A = Toeplitz(col, -col)
println("type of A: $(typeof(A))")
println("A isa Matrix: ", A isa Matrix)
:::

However, it does behave like an array in many ways. For instance, we can get its size:

:::{code-cell}
size(A)
:::

We've multiplied Toeplitz matrices with vectors using `*`, too. Julia has a way of indicating that an object is matrix-like:

:::{code-cell}
A isa AbstractMatrix
:::

Being subtyped from `AbstractMatrix`, the object `A` promises that even though it is not represented as a contiguous block of values in memory, it can do the basic things a matrix should do. Behind the scenes, meanwhile, special algorithms can be used to save time and memory.

A similar situation holds with ranges:

:::{code-cell}
N = 2:2:10
println("N isa Vector: ", N isa Vector)
println("N isa AbstractVector: ", N isa AbstractVector)
:::

Thus, while we can read an element of a range, we can't overwrite one:

:::{code-cell}
:tags: [raises-exception]
@show N[4]
N[1] = 2    # error, not mutable by index
:::

If you want to convert a range into a proper vector, you can apply `collect` to it. Conversion also happens automatically in some situations, like a vertical concatenation:

:::{code-cell}
println("collect(N) is a Vector? ", collect(N) isa Vector)
@show [1; N];
:::

Another such situation arises in line 28 of [Program 7](#p7). Since exponentiating the range `(-15:5:0)` creates an output that is not evenly spaced, the result is a vector.

:::{code-cell}
println("10.0 ^ (-15:5:0) is a Vector? ", 10.0 .^ (-15:5:0) isa Vector)
println("10 * (-15:5:0) is a Vector? ", 10 * (-15:5:0) isa Vector)
:::

::::{note} Generalized eigenvalue problem
:icon: false
:class: dropdown
The `eigen` function can solve the generalized eigenvalue problem $Av = \lambda Bv$. If $B$ is nonsingular, you can rewrite this as an ordinary eigenvalue problem $B^{-1}Av = \lambda v$, but it is not always desirable to do so. ::::{note} Minimizing allocations
:class: dropdown
:icon: false

Now that you are getting comfortable with basic Julia, it's time to look at one of the finer details. I have used `maximum` in many of the programs, including line 28 of [Program 23](#p23). The outcome of

:::julia
maximum(abs, UU)
:::

is the same as

:::julia
maximum(abs.(UU))
:::

But they are evaluated differently. The first version applies the `abs` function as a filter while iterating over the elements of the array. The second version creates a new array of the same size as `UU` to hold the absolute values, and then iterates through that array. 

We can see the impact of this difference by using the `@benchmark` macro from the BenchmarkTools package. In absolute terms, the difference is small, but in relative terms, the difference is substantial:

:::{code-cell}
using BenchmarkTools
A = randn(500, 500)
@benchmark maximum(abs, $A)
:::

:::{code-cell}
@benchmark maximum(abs.($A))
:::

Julia lets you achieve many things in multiple ways. Often, it doesn't matter much which you choose. But if a key section of code is taking more time than you like, Julia gives you the tools and fine-grained control to try alternatives.

::::{exercise}
:label: exr9-3D

If you don't want to explicitly form the matrix of the 3-D Laplacian for Exercise 9.4, there is an alternative approach (valid in MATLAB as well). Like all iterative methods based on Krylov subspaces, `eigs` can work with a function that computes the matrix-vector product $Av$ without ever forming the matrix $A$. This is most easily done in conjunction with the `LinearMaps` package. For example, here is how you would define a `LinearMap` for a diagonal matrix:

```julia
using LinearMaps
N = 20
d = 1:N     # diagonal entries
matvec(v) = d .* v   # matrix-vector product
L = LinearMap(matvec, N)
```

The resulting `L` could be used in place of `Diagonal(d)` in the `eigs` function. 

For the 3-D Laplacian, your equivalent of the `matvec` function has to reshape a vector input to an $(N-1) \times (N-1) \times (N-1)$ array, apply the 3-D Laplacian to it (for which `mapslices` is very handy), and then reshape the result back to a vector. At no point do you need to deal with Kronecker products.

If you want to visualize the eigenvectors, you will need to use `GLMakie` instead of `CairoMakie`, which doesn't support 3-D plotting.
::::
