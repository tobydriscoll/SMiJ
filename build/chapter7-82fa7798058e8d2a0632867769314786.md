## baryinterp and chebinterp

I have departed from the original `p13.m` significantly.[^bary] Rather than using `fit` to interpolate the solution to a finer grid like we did in [Program 9](#p9), I have used the barycentric interpolation formula presented in the exercises of Chapter 7. This is a much faster stable method, as Berrut and Trefethen made clear in a [paper](doi:10.1137/S0036144502417715) published after *SMiM*.

[^bary]: From personal communication with Trefethen, I know that he wishes in retrospect that the barycentric formula had played a more prominent role in *SMiM*.

A lot is going on here! This is our first look at a problem with two space variables. 

:::{warning}
History unfolded such that in a matrix, the first dimension is vertically oriented, while for a bivariate function, the first dimension is horizontally oriented. Because MATLAB predates widespread use of graphics-capable displays, it adopted the convention that in a matrix that represents the discretization of a bivariate function, the first dimension is vertically oriented. Matplotlib, being patterned after MATLAB, adopted the same convention. In modern contexts, this choice can create confusion, particularly when there are more than two independent variables.

In Julia, the `Plots` package follows the MATLAB convention, while `Makie` has the first dimension (rows) map to the first variable ($x$). That is my convention, too. If you see codes that swap the placement of $x$ and $y$ from what I use, or that have transposed matrices in plotting calls, that's probably what's going on.
:::

I have changed the interpolation algorithm from the code in *SMiM*, as I describe below  [in detail](#interp2d) following notes on the other aspects of the program.

### Interpolation in 2-D

I have chosen to use 2-D Chebyshev interpolation to get data on the plotting grid, whereas the program in *SMiM* used bicubic spline interpolation. The graphical outputs are very similar—but, as the contours in [Output 17](#output17) show, not identical. The spectral method is, naturally, more accurate.

Fortunately, it is not hard to turn one-dimensional interpolation into 2-D interpolation on a tensor product grid. Suppose we have an interpolation method $F$ that turns values on a grid $x_1,\ldots,x_m$ into a function $f$,

:::{math}
f(\xi) = F(v_1, \ldots, v_m; \xi),
:::
and another method $G$ that does the same for a grid $y_1,\ldots,y_n$,

:::{math}
g(\eta) = G(w_1, \ldots, w_n; \eta).
:::

Then with a matrix of grid values, $V_{ij} = u(x_i, y_j)$, we can define a 2-D interpolant by a nested application of the 1-D methods:

:::{math}
\begin{aligned}
w_j(\xi) &= F(V_{1j}, \ldots, V_{mj}; \xi), \quad j = 1, \ldots, n, \\
u(\xi, \eta) &= G(w_1(\xi), \ldots, w_n(\xi); \eta).
\end{aligned}
:::

Evaluation on a grid of values $\xi_1, \ldots, \xi_p$ and $\eta_1, \ldots, \eta_q$ leads to

:::{math}
\begin{aligned}
W_{ij} = w_j(\xi_i) &= F(V_{1j}, \ldots, V_{mj}; \xi_i), \quad i = 1, \ldots, p,\\
U_{ij} = u(\xi_i, \eta_j) &= G(W_{i1}, \ldots, W_{in}; \eta_j), \quad j = 1, \ldots, q.
\end{aligned}
:::
