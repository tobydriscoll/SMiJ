using CairoMakie, LaTeXStrings, LinearAlgebra, SpectralMethodsTrefethen
"""
p21 - eigenvalues of Mathieu operator -u_xx + 2 q cos(2x) u\n
         (compare p8 and p. 724 of Abramowitz & Stegun)
"""
function p21(N=42)
    x, _, D² = fourier(N)    # second-order differentiation matrix
    q = 0:.2:15
    data = zeros(11, length(q))
    for (i, q) in enumerate(q)
        λ = eigvals( -D² + 2q * Diagonal(cos.(2x)) )
        data[:, i] = λ[1:11]
    end
    fig = Figure(size=(320, 500))
    ax = Axis(fig[1, 1]; xlabel=L"q", ylabel=L"λ", yticks=-24:4:32,
        limits=(0, 15, -24, 32))
    series!(ax, q, data[1:2:end, :], color=:atlantic)
    series!(ax, q, data[2:2:end, :], linestyle=:dot, color=:atlantic)
    return fig
end

Now that you’re becoming comfortable with Julia basics, it’s a good time to say a bit more about its type system. For example, we’ve worked with Toeplitz matrices several times. But to be precise, a Toeplitz matrix isn’t a Matrix in Julia:

using ToeplitzMatrices
col = [0.; -2; 6; zeros(3)]
A = Toeplitz(col, -col)
println("type of A: $(typeof(A))")
println("A isa Matrix: ", A isa Matrix)
type of A: Toeplitz{Float64, Vector{Float64}, Vector{Float64}}

A isa Matrix: false

However, it does behave like an array in many ways. For instance, we can get its size:

size(A)
(6, 6)

We’ve multiplied Toeplitz matrices with vectors using *, too. Julia has a way of indicating that an object is matrix-like:

A isa AbstractMatrix
true

Being subtyped from AbstractMatrix, the object A promises that even though it is not represented as a contiguous block of values in memory, it can do the basic things a matrix should do. Behind the scenes, meanwhile, special algorithms can be used to save time and memory.

A similar situation holds with ranges:

N = 2:2:10
println("N isa Vector: ", N isa Vector)
println("N isa AbstractVector: ", N isa AbstractVector)
N isa Vector: false
N isa AbstractVector: true

Thus, while we can read an element of a range, we can’t overwrite one:

@show N[4]
N[1] = 2    # error, not mutable by index
N[4] = 8

println("collect(N) is a Vector? ", collect(N) isa Vector)

using CairoMakie, LaTeXStrings, Printf
using LinearAlgebra, ToeplitzMatrices, SpecialFunctions, SpectralMethodsTrefethen
"p22 - 5th eigenvector of Airy equation u_xx = λ*x*u"
function p22()
    fig = Figure(size=(600, 600))
    N = [12 24; 36 48]
    for (i, N) in pairs(N)
        D, x = cheb(N)
        D² = (D^2)[2:N, 2:N]
        λ, V = eigen(D², diagm(x[2:N]))         # generalized ev problem
        fifth = findfirst(>(0), λ) + 4
        λ, v = λ[fifth], V[:, fifth]
        v = [0; v; 0]                           # extend to booundary
        v = v / v[div(N, 2) + 1] * airyai(0)    # normalize
        u = chebinterp(v)
        lines(fig[i[1], i[2]], -1..1, u;
            axis=(; title=@sprintf("N = %d,  λ = %0.10f", N, λ)))
    end
    return fig
end

You probably won’t use special functions like Airy functions often, but when you do need them, the SpecialFunctions package provides a large collection of them.

Generalized eigenvalue problem

The eigen function can solve the generalized eigenvalue problem Av=λBvAv = \lambda BvAv=λBv. If BBB is nonsingular, you can rewrite this as an ordinary eigenvalue problem B−1Av=λvB^{-1}Av = \lambda vB−1Av=λv, but it is not always desirable to do so. (However, that is the algorithm used if BBB is a Diagonal matrix, so here we have to use a generic matrix instead to avoid an error due to the singularity of BBB.)

findfirst

The findfirst function returns the index of the first element of an array that satisfies a given condition. The result is either nothing, if no elements satisfy the condition, or an integer index. I have used the syntax >(0) to create an anonymous function that tests whether its argument is greater than zero, shorthand for x -> x > 0. Finally, we want the 5th index of the result, so I add 4 since they are in sorted order.

using CairoMakie, Printf, LaTeXStrings
using LinearAlgebra, SpectralMethodsTrefethen
"""
# p23 - eigenvalues of perturbed Laplacian on [-1,1] x [-1,1] (compare p16)
"""
function p23(N=16; perturb=false)
    # Set up tensor product Laplacian and compute 4 eigenmodes:
    D, x = cheb(N)
    y = x

    D² = (D^2)[2:N, 2:N]
    Δ = -kron(I(N-1), D²) - kron(D², I(N-1))    # Laplacian
    if perturb
        F = [exp(20 * (y - x - 1)) for x in x[2:N], y in y[2:N]]
        Δ += Diagonal(vec(F))
    end
    λ, V = eigen(Δ)

    # Reshape them to 2D grid, interpolate to finer grid, and plot:
    xx = yy = range(-1, 1, 101)
    U = zeros(N+1, N+1)
    fig = Figure(size=(600, 600))
    modes = [1 2; 3 4]
    ax = [Axis(fig[i, j]; aspect=1) for i in 1:2, j in 1:2]
    for (i, mode) in pairs(modes)
        U[2:N, 2:N] = reshape(V[:, mode], N-1, N-1)
        UU = interp2dgrid(U, chebinterp, chebinterp, xx, yy)
        UU /= maximum(abs, UU)
        str = @sprintf("λ = %0.12f π^2/4", 4λ[mode] / π^2)
        contourf!(ax[i], xx, yy, UU; levels=-1.1:0.2:1.1, colormap=:redsblues)
        ax[i].title = str
        hidedecorations!(ax[i], ticks=false)
    end
    return fig
end

Minimizing allocations

Now that you are getting comfortable with basic Julia, it’s time to look at one of the finer details. I have used maximum in many of the programs, including line 28 of Program 23. The outcome of

maximum(abs, UU)

is the same as

maximum(abs.(UU))

But they are evaluated differently. The first version applies the abs function as a filter while iterating over the elements of the array. The second version creates a new array of the same size as UU to hold the absolute values, and then iterates through that array.

We can see the impact of this difference by using the @benchmark macro from the BenchmarkTools package. In absolute terms, the difference is small, but in relative terms, the difference is substantial:

using  CairoMakie, LinearAlgebra, SpectralMethodsTrefethen
"p24 - pseudospectra of Davies's complex harmonic oscillator"
function p24(N=70, L=6)
    # Eigenvalues:
    D, x = cheb(N)
    x, D = L * x, D / L            # rescale to [-L,L]
    A = -D^2 + (1 + 3im) * Diagonal(x .^ 2)
    A = A[2:N, 2:N]
    λ = eigvals(A)

    # Pseudospectra:
    fig = Figure()
    ax = Axis(fig[1, 1]; xlabel=L"\mathrm{Re}(z)", ylabel=L"\mathrm{Im}(z)",
        limits=(0, 50, 0, 40), aspect=DataAspect())
    x, y = 0:0.5:50, 0:0.5:40
    minsigma(z) = minimum(svdvals(z * I - A))
    σ_min = [minsigma(complex(x, y)) for x in x, y in y]
    cplt = contourf!(x, y, log10.(σ_min); colormap=:Blues, levels=-5:0.5:-0.5)
    scatter!(ax, reim(λ)...; color=:orange, markersize=8)
    Colorbar(fig[1, 2], cplt)
    return fig
end

SMiM Exercise 9.4

The eigs function is found in the Arpack package and works similarly to the one in MATLAB. Also, to make the Laplacian matrix sparse, import SparseArrays and apply sparse to the 1-D differentiation matrix; a Kronecker product of that with I will remain sparse.

SMiM Exercise 9.8

I’m not aware of a Julia equivalent for the EigTool package referred to in this exercise. In principle, you can speed up pseudospectra computation a great deal by finding an orthogonal similarity transformation of the matrix to Hessenberg form before computing singular values. However, it appears that to exploit that structure in Julia, you have to make direct calls to the LAPACK library.

Exercise 1

If you don’t want to explicitly form the matrix of the 3-D Laplacian for Exercise 9.4, there is an alternative approach (valid in MATLAB as well). Like all iterative methods based on Krylov subspaces, eigs can work with a function that computes the matrix-vector product AvAvAv without ever forming the matrix AAA. This is most easily done in conjunction with the LinearMaps package. For example, here is how you would define a LinearMap for a diagonal matrix:

using LinearMaps
N = 20
d = 1:N     # diagonal entries
matvec(v) = d .* v   # matrix-vector product
L = LinearMap(matvec, N)

The resulting L could be used in place of Diagonal(d) in the eigs function.

For the 3-D Laplacian, your equivalent of the matvec function has to reshape a vector input to an (N−1)×(N−1)×(N−1)(N-1) \times (N-1) \times (N-1)(N−1)×(N−1)×(N−1) array, apply the 3-D Laplacian to it (for which mapslices is very handy), and then reshape the result back to a vector. At no point do you need to deal with Kronecker products.

If you want to visualize the eigenvectors, you will need to use GLMakie instead of CairoMakie, which doesn’t support 3-D plotting.
